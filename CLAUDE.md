# Kharcha — project context for agents

Kharcha is a **local-first Android personal expense tracker for India**. Its core job:
automatically record and categorize spending from Android transaction notifications (UPI apps,
bank apps, card apps, and bank SMS as shown by the SMS app), so the user reviews exceptions
instead of typing every expense. Manual entry is only a fallback (cash).

The owner is comfortable with React/TypeScript and has little Kotlin experience: keep native
code small and isolated; everything else is TypeScript.

**`docs/ARCHITECTURE.md` is the contract** (pipeline, dedup rules, categorization precedence,
accounting rules, safe-to-spend formula, folder structure). Read it before changing any module.

## Working rules for this repo

- **Never commit real financial data.** No real SMS, notification text, account numbers,
  names or transactions — in code, fixtures, tests, docs or issues. Fixtures in
  `test/fixtures/notifications/` are synthetic. Real data lives only on the phone.
- **No backend, no network calls with user data, no analytics/crash SDKs, no LLM parsing.**
  Parsing is deterministic (regex/rules) and unit-tested.
- **Native code lives only in `modules/`** (local Expo module). `android/` is generated by
  `npx expo prebuild` and is git-ignored — never edit it by hand.
- Add dependencies with `npx expo install <pkg>` only. Don't add a dependency when a few lines of
  code will do.
- Money = integer minor units (paise). Time = epoch ms, local time zone. IDs = UUIDv7
  (`src/utils/ids.ts`). Built-in category IDs are stable keys like `food.food_delivery`.
- Before declaring work done: `npm run check` (typecheck + Jest). Tests run with
  `TZ=Asia/Kolkata`.
- Keep this file up to date: when a phase completes or a decision changes, update
  **Status** and **Decisions** below.
- **Git/history:** development started on a company-managed work laptop where git must not be
  used (wrong identity). The code is moved to the owner's personal machine as a zip, where the
  real repository lives. Do not assume any history before that.

## Decisions (and why)

- **Expo SDK 57 + CNG + one local Expo module** instead of bare RN 0.87: easiest path for a
  React developer; Expo Modules API (Kotlin DSL) is well documented. Upgrade to SDK 58 once
  stable (≈ Oct 2026) — test R8 minification of the module then.
- **Kotlin persists, TypeScript processes.** The listener writes every money-looking notification
  (package allowlist OR money regex) into its own `queue.db`; JS drains it on app start/resume
  and when notified. The SMS reader queries recent money-looking inbox rows and hands them to the
  same pipeline; a stable SMS provider row id makes repeated syncs idempotent. **No Headless JS in V1**:
  it has open New-Architecture bugs (timers stalled
  on Samsung One UI; expo-dev-launcher asserts if ReactHost was started by a service). Nothing
  is lost because the queue is durable.
- **Two SQLite files, one owner each** (`queue.db` = Android framework SQLite in Kotlin;
  `kharcha.db` = expo-sqlite in JS). Two SQLite libraries on one file in one process can corrupt it.
- **Raw events are immutable and kept** → parsers can be fixed and history re-processed
  (`raw_events.pipeline_version`).
- **Two-layer dedup**: content hash for re-posted notifications; cross-source matching (UPI RRN,
  amount, time window, account last4, merchant) for "same payment seen by GPay + bank SMS".
  Low confidence → Review, never silent deletion.
- **Accounting**: transfers (own-account, credit-card bill payment, wallet/UPI Lite top-up, ATM
  withdrawal, investments/savings) never count as spending; refunds reduce spending; suspected
  duplicates are excluded until resolved.
- **Expo Router** for navigation (built on React Navigation); **Zustand** only for UI state —
  SQLite is the source of truth.
- **expo-sqlite** (WAL, foreign keys) behind a small `SqlDatabase` interface; repositories are
  tested against real SQLite via `node:sqlite` (Node 24).
- **Listener intake:** keep a notification only if its text has a money pattern, Android hid it
  ("Sensitive notification content hidden"), or its package is on the JS allowlist (UPI/bank/
  card/merchant apps — **never SMS apps**, so personal SMS are dropped natively). Notifications
  without any amount keep no text in `raw_events`. Hidden ones show as one summary card in Review.
- **Raw-event idempotency is a ±2 min window on the content hash**, not a unique constraint, so
  two identical ₹10 payments minutes apart are both kept.
- **Postgres/Supabase is not used in V1** (local-first rule). The schema is sync-ready (UUIDv7,
  `updated_at`, `deleted_at`); an opt-in encrypted backup/sync can be added later.
- **Charts are plain Views** (no chart/SVG dependency) — enough for bars and share bars.
- **`.npmrc` sets `legacy-peer-deps=true`**: Expo SDK 57 has conflicting optional peer ranges
  (`react-dom`; `react-native-worklets` via expo-router → drawer → reanimated). Needed peers are
  pinned explicitly: `react-dom` 19.2.3 (= react), `expo-modules-core` (jest-expo needs it
  hoisted), `@react-native/jest-preset` 0.86.3 (must match react-native). Verify any dependency
  change with a clean install (`rm -rf node_modules package-lock.json && npm install`).

## Research findings that shape the design (verified Sept 2026)

- **No backfill**: a NotificationListenerService only sees notifications posted while it is
  bound; `getActiveNotifications()` on connect recovers what is still in the shade.
- **Android 15+ OTP redaction**: untrusted listeners get "Sensitive notification content hidden"
  for notifications the system thinks contain an OTP. AOSP only checks the default SMS app, with a
  regex that can misfire on bank SMS (e.g. `XX1234`). Store redacted events as `redacted` and show
  them in Review. For the owner's own phone:
  `adb shell appops set --user 0 app.kharcha RECEIVE_SENSITIVE_NOTIFICATIONS allow`, then toggle
  notification access (unverified on OEM ROMs).
- **Small UPI payments may have no bank SMS**: HDFC skips UPI SMS ≤ ₹100 debit / ≤ ₹500 credit
  since 2024; from **1 Jan 2027 RBI only mandates instant SMS for transactions > ₹500**. UPI Lite
  payments get no per-transaction SMS. ⇒ UPI-app notifications are essential, SMS is not enough.
- **Banks are moving alerts to RCS** (display-name senders, not stored as SMS) — the notification
  listener on the SMS app still sees them; SMS-inbox reading would not.
- **UPI 12-digit reference (RRN)** is the best dedup key when present; UPI-app notifications often
  omit it ⇒ fuzzy fallback (amount + time + account/merchant).
- **Look-alikes to reject**: OTPs, cashback/loan offers, bill-due reminders, statements, collect
  requests, mandate creation, and **AutoPay pre-debit notices** ("₹649 will be debited on …").
- **Self-transfers** produce a debit and a credit with the same RRN → must become one transfer.
  Failed payments can be followed a day later by a reversal carrying the same reference.
- **OEM battery killers** (Xiaomi, OnePlus, Samsung, Oppo, Vivo) can unbind the listener ⇒ listener
  health check (`requestRebind`), onboarding checklist (autostart, battery unrestricted).
- **Distribution in India**: Play Protect blocks installing apps that use a notification listener
  from browsers/messaging apps/file managers. **Install via `adb` / `npx expo run:android`**
  (also avoids Android 13+ "restricted settings"). Android developer verification (global 2027)
  exempts adb installs. A Play release would later need a Prominent Disclosure, privacy policy,
  and (new personal accounts) a 12-tester × 14-day closed test.
- **Signing key continuity**: reinstalling with a different signing key forces an uninstall, which
  deletes all on-device data. Create a personal release keystore before daily use, and build
  export/backup early.

## Development setup

Requirements: Node ≥ 24.3 (or 22.13+), JDK 17, Android SDK (platform 36 for Expo SDK 57; the
build auto-downloads missing platform/build-tools once licenses are accepted), NDK 27.1.

```bash
npm install
npm run check                 # typecheck + unit tests
npx expo prebuild -p android  # generate android/ (after native/module/config changes)
npx expo run:android          # build + install on emulator or USB device, starts Metro
```

**macOS (owner's personal machine):** install Temurin JDK 17 and Android Studio (or the
command-line tools), set `JAVA_HOME` and `ANDROID_HOME=$HOME/Library/Android/sdk`, add
`$ANDROID_HOME/platform-tools` to `PATH`, then the commands above.

**Real phone:** enable Developer options → USB debugging, connect, `adb devices`, then
`npx expo run:android --device`. Samsung One UI 6.1.1+: turn off *Auto Blocker* first.
Grant notification access in Settings, or for development:
`adb shell cmd notification allow_listener app.kharcha/expo.modules.notificationlistener.KharchaNotificationListenerService`.

**Synthetic test notifications:**
`adb shell cmd notification post -S bigtext -t 'Title' tag 'Rs.124.00 paid to Zomato'` (posted
as `com.android.shell` — only accepted in debug builds), and on the emulator
`adb emu sms send AXTESTBK 'Rs.124.00 debited from A/c XX1234 …'` (arrives as a Google Messages
notification with the sender as title).
